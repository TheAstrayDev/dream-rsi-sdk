# Architecture

The fixed discovery agent and evaluator produce immutable discovery trees. Policies choose root/leaf expansions from revealed information. Strict replay reads recorded transitions; it never predicts unrecorded outcomes. A developer can rewrite executable exploration source, test it on training replay and submit the strongest candidate to a promotion gate. See [the research](https://arxiv.org/html/2609.14858v1) and the [implementation contracts](docs/research-loop.md).

## Modules

| Module | Responsibility |
| --- | --- |
| `runtime.py` | Online attempts, event persistence, extension routing, metered dispatch |
| `methods.py` | Replaceable outer loop and checkpoint boundaries |
| `developer.py` | Model request → source → replay feedback → revision |
| `sandbox.py` | Bounded SDK-language interpreter; no Docker or generated bytecode execution |
| `process_sandbox.py` | Optional fresh worker, hard termination and event-loop isolation for interpreter decisions |
| `artifacts.py` | Source hashes/provenance and explicit policy serialization |
| `replay/`, `views.py` | Recorded-transition execution and shared prefix-visible context |
| `validation.py` | Independent collection and single-use validation batches |
| `accounting.py` | Shared reservations, usage reports, uncertainty and overruns |
| `checkpoints.py`, `storage/` | Versioned JSON state and transactional SQLite persistence |
| `integrations.py`, `workspaces.py` | Runnable integration and external snapshot lifecycle |

## Invariants

- The developer changes policy source, not agent weights or task scoring.
- Only revealed nodes, observations and child counts reach policy views.
- Candidate policies and incumbent use the same training worlds and objective.
- Holdout feedback never enters developer requests; consumed batches are not reused.
- Source loading checks integrity and never executes code. Interpretation starts only at a policy decision.
- Resource reservations precede external dispatch. Unknown costs stay estimated and reserved.
- A committed online tree survives a dreaming interruption. Uncertain external calls are not silently repeated after restart.
- Live model clients, browser handles and DB sessions remain in adapters/backends, not discovery state.

## Limits and recovery semantics

The interpreter supports a documented Python-syntax subset, not arbitrary Python. Logical allocation/operation limits are not OS memory quotas. The SDK cannot enforce provider pricing or terminate a remote job without adapter support. JSON-compatible descriptors and durable backend snapshots are required for persistence. User-defined component changes must update `experiment_version`. A finite holdout experiment supplies evidence, not proof of generalization.

The complete gap-by-gap status is in [hardening.md](docs/hardening.md). The
[Bonsai experiment](docs/experiments/bonsai-2026-09-22.md) records real source repair,
replay, held-out promotion, serialization and fresh online execution, including failures.
StrictReplay coefficients participate in recovery fingerprints. Ambiguous validation
collection is journaled and requires explicit reconciliation before abandonment.
