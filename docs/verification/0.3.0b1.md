Collected locally on 2026-10-04. The figures distinguish **measured interpreter
time**, an **exact accounting example**, and an **exhaustive deterministic runtime

## Sandbox timing

![Paired cache-off and cache-on interpreter timings](../../assets/beta-sandbox-performance.png)

The existing [balanced source policy](../../examples/balanced_source.py) ran with
identical views and the original balanced profile. Each of seven samples creates
a fresh sandbox and executes 1,000 decisions. Cache-off and cache-on order alternates
between pairs. Every returned decision must match. Bars show medians; dots show
all samples, including slower outliers. Results include parsing the first use.

| View | Cache disabled | Cache enabled | Median speedup |
| --- | ---: | ---: | ---: |
| One frontier node | 0.409 s | 0.141 s | 2.90x |
| Eight frontier nodes | 0.971 s | 0.689 s | 1.41x |
| Empty frontier | 0.265 s | 0.033 s | 8.01x |

Times are per 1,000 decisions on one local Windows machine. Repeated measurements
and other machines can differ. These figures do not measure model latency, the
fresh-process backend, provider calls, tokens, dollars or campaign speed.

## Dynamic preparation allowance

![Exact allowance example against a strict 23-call cap](../../assets/beta-preparation-headroom.png)

The planned baseline is six tasks at four calls each. Two preparation calls and
eight deployment calls on two completed tasks have already been spent. Four
unfinished tasks reserve one call each. The dynamic limit is
`24 - 1 - 2 - 8 - 4 = 9` further preparation calls; a static preparation-only limit
would allow 15. The extra six would exceed the strict cap even at the optimistic
deployment floor. This is an arithmetic admission example, not observed savings.

The plotted optimistic total is 29 for the static allowance and 23 for the dynamic
allowance. A task requiring more than the floor can still miss the savings target.
The economic limit leaves quality-preserving deployment fallback intact.
See [the integer derivation](../all-in.md).

## Exhaustive quality preservation

![Equal returned quality in all 243 deterministic SDK cases](../../assets/beta-quality-preservation.png)

The collector executes **both arms through `DreamRSI.run`**, with the same
deterministic state transition, raw-quality metric, initial candidate and budgets:

- Four future values from `{0, 0.5, 1}` and one initial value from the same set:
  `3^5 = 243` cases, 81 for each initial quality.
- `FixedParallelPolicy(branches=1, max_depth=4)`, four agent-call slots, five
  evaluator-call slots and parallelism one.
- The contract's bound is valid by construction: every candidate quality is at most one.
- The reference uses `certified_stopping=False`; the protected arm uses the same
  contract with certified stopping enabled.

The collector checks the actual returned answer, expected maximum, shared contract
metadata, baseline-prefix observations and initial evaluation charges.

| Across all 243 cases | Full reference | Certified stopping |
| --- | ---: | ---: |
| Raw-quality mismatches | 0 | 0 |
| Logical agent dispatches | 972 | 390 |
| Local evaluator calls, including initial candidates | 1,215 | 633 |
| Initial local evaluator calls | 243 | 243 |
| Cases using fewer than four agent dispatches | 0 | 195 |
| External model requests | 0 | 0 |

Enumeration is not a workload-frequency estimate. The call counts are logical
adapter dispatches. There are no provider measurements or claims of LLM dollar
or token savings. The no-loss argument requires a sound bound and matching
reference semantics; see [the quality contract](../quality-contract.md).

## Reproduce locally

Install the source SDK and development tools first. These collectors need no model,
API key or network. They write only local engineering data under ignored `temp/`:

```bash
python -I tools/collect_beta_quality.py --output temp/beta-quality.json
python -I tools/measure_beta_sandbox.py --output temp/beta-sandbox.json
python -m pytest tests/test_quality_contract.py tests/test_dynamic_economy.py tests/test_sandbox_usability.py -q
```

To rerender the frozen English PNG/SVG figures, plotting dependencies are needed
only in the development environment; the SDK still has zero required dependencies:

```bash
python -m pip install matplotlib numpy
python tools/render_beta_figures.py
```

The renderer reads the curated JSON; collecting fresh timing data does not silently
replace the published figure evidence.
