# Dream-RSI SDK 0.2.0a4 — Replay-derived stopping policies

Derive a shorter exploration policy from recorded experience without asking
a developer model to write a stopping rule. This release also tightens the
recorded-tree cost bound used to skip futile source-development requests.
Dream-RSI SDK remains an independent, unofficial project by **TheAstrayDev**,
unaffiliated with Google or Google DeepMind.

## Stop after the useful recorded prefix

The deterministic optimizer finds the first complete decision round reaching
each training world's final raw quality, then takes the maximum of those
round numbers. `PrefixPolicy` delegates unchanged to the incumbent until that
cap. It supports built-in and executable source policies, retains full parallel
batches and stays inside the configured candidate count. Custom policies can
participate and require registered codecs when persisted.

```python
from dreamrsi import DefaultMethod, DreamRSI, DreamRSIConfig, HoldoutPipeline

sdk = DreamRSI(
    adapter=my_adapter,
    evaluator=my_evaluator,
    policy=my_policy,
    budget=my_budget,
    method=DefaultMethod(online=False),
    validation=HoldoutPipeline(independent_tasks),
    config=DreamRSIConfig(optimizer_prefix_search=True),
)

run = await sdk.run(task)
await sdk.record_world(task, run)
improvement = await sdk.improve(task, rounds=1)
champion = improvement.champion_policy
```

Use your agent, evaluator, policy, budget and independent validation tasks in
this example. Acquisition and validation are charged normally. Synthesis
itself makes no model requests. When history is already recorded, the offline
improvement pass can reuse it instead of acquiring another training run.

The smallest common prefix preserves quality on the **checked history**, not
on arbitrary future tasks. Every candidate is replayed and passes the existing
promotion gate; independent validation remains essential. The optimizer uses
`HoldoutPipeline.quality_metric` when configured to separate raw quality from
composite task scores. The original replay objective is unchanged.

## Controls, persistence and cost bounds

- Disable automatic prefix proposals with
  `DreamRSIConfig(optimizer_prefix_search=False)`. Standalone
  `DeterministicPolicyOptimizer(prefix_search=False)` retains the earlier portfolio.
- Save and reload prefix policies through `PolicyCodec`, campaign checkpoints
  and portable policy-memory bundles. Nested source artifacts retain their
  integrity checks and sandbox configuration.
- Under strict replay, reaching depth `d` in one-based root branch `b` needs
  at least `b + d - 1` probes. The developer eligibility check now respects this
  ordering. Unknown evidence and custom replay semantics remain eligible.

## Upgrade

```bash
python -m pip install --upgrade dreamrsi==0.2.0a4
```

Existing trees and older built-in/source policy bundles remain readable.
Bundles containing the new prefix kind require **0.2.0a4 or newer** on the
receiving side. The runtime configuration fingerprint now includes prefix
search settings: use a new campaign ID for older checkpoints. Importing policy
memory does not restore an old campaign's runtime state.

This release changes policy search and persistence, not model weights. It
does not claim a general real-model all-in cost advantage. Preparation, failed
requests, validation and deployment must all be counted when evaluating savings.

Local verification on the clean release source: **254 tests passed**, two
optional integration checks skipped; Ruff and Pyright passed. Wheel and source
distributions built successfully. Local benchmark files are excluded.

See the [prefix guide](https://github.com/TheAstrayDev/dream-rsi-sdk/blob/main/docs/replay-prefix.md)
for the proof, configuration and all-in economics, and the
[README](https://github.com/TheAstrayDev/dream-rsi-sdk#readme) for integration.
