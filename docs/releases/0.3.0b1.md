## Quality before savings

`QualityContract` separates raw answer quality from work penalties. The strict
default keeps the original policy's decisions and complete batches. It can skip
later calls only when the best valid answer exactly reaches a sound task upper
bound. Missing, invalid or contradicted bounds continue the original search.
The actual returned observation is selected by raw quality; a higher composite
score cannot substitute a worse answer.

```python
from dreamrsi import Budget, DreamRSI, EconomyPlan, QualityContract

def raw_quality(record):
    return record["observation"]["raw_quality"]

sdk = DreamRSI(
    adapter=my_adapter,
    evaluator=my_evaluator,
    policy=my_original_policy,
    budget=Budget(model_calls=4),
    quality=QualityContract(
        id="my-task-quality-v1",
        metric=raw_quality,
        upper_bound=1.0,
    ),
    economy=EconomyPlan(baseline_calls_per_task=4, horizon=6),
)
result = await sdk.run(task)
print(result.metrics["raw_quality"])
```

Use your own integrations. `1.0` must be a proven bound for the feasible answer
domain, not a sampled training maximum. A fair reference uses the same evaluator,
raw-quality selector, initial candidate and budgets. When a holdout pipeline is
supplied, it must use the same raw-quality extractor.

Use the same contract with `certified_stopping=False` for a full-search reference.
This preserves input metadata in both arms. The guarantee compares a common
response trajectory; it does not make independent random runs identical or
ensure that a wall-time cutoff obtains the same answers.

Strict certified stopping requires no policy training: `run` uses the current
task's revealed evidence. `improve` skips source generation and repeated
training in this mode. An optional initial candidate is evaluated, charged and
retained if later answers are worse. Its evaluation consumes a budget slot.

`preserve_policy=False` explicitly enables empirical strategy/source rewrites.
Applications without a quality contract retain the earlier workflow. Finite
replay and holdout evidence cannot guarantee no loss on every unseen task.

## Complete all-in costs

The exact savings condition is:

```text
historical preparation + new preparation < sum(baseline calls - deployment calls)
```

`EconomyPlan` uses exact integer arithmetic to cap preparation after reserving
an optimistic deployment floor. Before every preparation request it subtracts
actual spending and reserves only unfinished tasks:

```text
remaining = max(0, H*B - 1 - historical - preparation - deployment - max(0, H-done)*m)
```

The completed-deployment counter survives campaign recovery. Declared nested-call
ceilings are checked before dispatch. With a 24-call baseline horizon, two
preparation calls and eight calls across two completed deployments, this permits
nine further preparation calls instead of fifteen. The difference prevents
unaffordable development; it is not evidence of a model-quality improvement.
Preparation and deployment are recorded separately.

![Exact preparation headroom example, separate from model benchmarks](../../assets/beta-preparation-headroom.png)

Shared request limits include reported nested provider calls, LLM evaluators,
failed requests and retries. Recovered ledgers retain their charges. Measured
payback includes historical preparation; unknown tokens and dollars stay unknown.

The plan does not truncate quality-preserving fallback search to manufacture a
saving. A task that needs every baseline call can miss the economic target.

## Easier, faster sandbox configuration

```python
from dreamrsi import PolicySandbox, ProcessPolicySandbox, SandboxConfig

sandbox = PolicySandbox.from_preset("large", max_steps=2_000_000)
SandboxConfig.preset("large").save("sandbox.json")
worker = ProcessPolicySandbox.from_file("sandbox.json")
```

The finite `small`, `balanced` and `large` profiles enable all supported language
features. Individual limits and allowlists remain configurable; `balanced` matches
the prior default. Configuration files store effective settings and refuse accidental
overwrite. The inline sandbox caches validated syntax trees by source and profile,
keeping every interpreter, observation and resource check fresh. The cache is bounded,
can be disabled and does not store answers or policy state.

A paired deterministic timing test measured **2.90x** speedup with one frontier node,
**1.41x** with eight, and **8.01x** for an empty frontier. This measures interpreter
work, not end-to-end model speed or LLM savings. Process execution still uses a fresh
killable worker per decision. See [configuration and timings](../sandbox.md).

## Beta integration and compatibility

- Public structural `PolicyDeveloper` protocol, alongside replaceable agents,
  replay engines, objectives, methods, stores and promotion gates.
- Existing v1 and legacy tree/policy payloads remain readable; unsupported
  explicit schema versions fail with a clear error.
- Nested `CertifiedPolicy`, source policies and ordinary policies round-trip
  through artifacts, checkpoints and portable bundles. Certified bundles require
  `0.3.0b1` or newer and the recipient's matching quality contract.
- Contract identities and economic settings participate in checkpoint matching.
  Changing their semantics requires a new identity and campaign.
- Raw-quality callback inputs are defensive copies, preventing a mutating callback
  from damaging the recorded answer or stopping certificate.
- Wrapped source policies recover their sandbox backend and resource profile.
- Built-in stores atomically reserve holdout identities, preventing duplicate use
  across concurrent memory instances or SQLite connections. Legacy custom stores
  serialize reservations within one memory instance; shared custom backends need
  the optional atomic checkpoint operation.
- Installed-wheel gates exercise the CLI, codecs and actual process sandbox
  outside the source checkout on Linux and Windows in the configured CI matrix,
  and again before distribution upload in the PyPI publication workflow.

## Latest local LLM follow-up

![Bonsai Q2 calls, quality and historical payback](../../assets/bonsai-structural-dream-2026-10-05.png)

An isolated structural-transfer experiment on eight new two-feature Lasso tasks
used real local Bonsai Q2 answers, with empty starting memory. The recovered
matched comparison needed **10 Dream calls including preparation versus 16
baseline calls**, with paired raw quality preserved and six exact optima versus
four. This is **37.5% fewer fresh-campaign calls**, not a dollar-ROI claim.

One baseline request timed out. A separately frozen two-call control repeat
confirmed the affected task; the primary success flag stays false. All **28
actual calls** remain accounted for, and earlier research costs have not paid
back. The structural module is not shipped in this SDK and did not write policy
code. See the [full conditions and curated data](../verification/bonsai-structural-dream-2026-10-05.md).
