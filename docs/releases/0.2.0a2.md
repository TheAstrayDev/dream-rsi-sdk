# Dream-RSI SDK 0.2.0a2 — Share policies and replay datasets

Policy reuse can now cross project and machine boundaries. A developer can export
saved policy versions and discovery trees as a portable JSON file; another developer
can import that file into their own SQLite memory and use it with a compatible agent.
GitHub repositories and release assets provide public distribution without a separate
Dream-RSI service.

## Why 0.2.0a2

`0.2.0a1` introduced durable policy reuse within an application. `0.2.0a2` adds
portable bundles and a GitHub package workflow on top of that memory. This is an
additive second alpha, not a stable API promise or a new performance claim. Existing
in-memory integrations do not need package sharing. The SDK remains an independent,
unofficial project by **TheAstrayDev**, unaffiliated with Google or Google DeepMind.

## How it works

![Dream-RSI workflow: export policy versions and recorded trees, share a JSON bundle, import into local memory, run and evaluate before reuse or further development.](https://github.com/TheAstrayDev/dream-rsi-sdk/releases/download/v0.2.0a2/package-sharing-0.2.0a2.png)

The recipient still runs their own agent on each new task. A matching policy that
meets the recipient's quality floor avoids a new policy-development pass. A missing
or degraded policy can trigger offline improvement from accepted recorded trees.
Trees describe observed transitions; replay cannot invent unseen outcomes. Training
can also be disabled, in which case degradation is reported without starting it.

## What ships

| Capability | Behavior in this release |
| --- | --- |
| Portable family bundle | Policy versions, active version, source/configuration where supported, origin metadata, recorded tasks, replay trees and checksums |
| Multi-family package | Several family bundles in one file; installation checks all local policy conflicts before importing |
| `dreamrsi list` | Public repositories tagged `dreamrsi-package`, ordered by GitHub stars |
| `dreamrsi install OWNER/REPOSITORY` | Downloads the latest package release, validates it and imports into local SQLite memory |
| `dreamrsi save NAME --all` | Exports every saved family in the selected namespace, without model requests |
| `dreamrsi publish PATH` | Uses GitHub CLI browser authorization, asks for an available repository name, uploads the package and registers its topic |
| Local Python transfer | `export_bundle` / `import_bundle` for a single family without GitHub |
| Application control | Independent save/reuse switches, acceptance hooks, quality floor and permission to train |

Checksums detect changed content; they are not author signatures or evidence of
quality. A bundle contains no model weights, credentials supplied by the SDK, agent
implementation, live browser session or running campaign checkpoint. Recorded task
data may itself contain private content, so review the file before publishing.

## Save, publish and install

Run these commands from your project directory. The default database is
`.dreamrsi/memory.sqlite3`, namespace `default`; it must already contain saved data.
Plain `DreamRSI.run()` with an in-memory store does not create this database.

```bash
dreamrsi save my-policy-pack --all
dreamrsi publish .dreamrsi/packages/exports/my-policy-pack.dreamrsi.json
```

For another SQLite database, use `-d PATH -n auto`. Auto selects a namespace only
when exactly one contains saved families. Otherwise specify `-n NAME`. Relative
paths are resolved from the current directory. Existing export files are protected:
use a new name or `--output another-file.dreamrsi.json` for another snapshot.

Publishing requires [GitHub CLI](https://cli.github.com/) on `PATH`. On Windows,
reopen the terminal after installing it. The CLI prompts for browser authorization
when needed and creates a **public** repository under the signed-in account.
Repository names are unique per account. The initial shared-data package release
is `v0.1.0`; that version is separate from SDK version `0.2.0a2`.

The recipient discovers or installs a real package reference:

```bash
dreamrsi list
dreamrsi install OWNER/REPOSITORY
```

`OWNER/REPOSITORY` is a placeholder for an actual published package. A new topic may
take time to appear in search. Direct installation works independently of indexing.
Downloaded files go under `.dreamrsi/packages/OWNER/REPOSITORY/`; imported data goes
into `.dreamrsi/memory.sqlite3`. The manifest's `bundle_files` mapping identifies
each family file in a multi-family package.

## Connect an imported policy and its trees to your agent

This complete recipient example targets a **numeric-halving:v1** bundle: task state
contains `kind` and `x`, and raw quality is `-x²` (higher is better). It deliberately
disables automatic training for the first integration check. Replace the toy agent,
evaluator, family contract and quality floor with your application's equivalents.
Changing only the family label does not make unrelated tasks compatible.

```python
import asyncio
from pathlib import Path

from dreamrsi import (
    AdaptivePolicyMemory, Budget, DefaultMethod, DreamRSI,
    FunctionalAgentAdapter, HoldoutPipeline, PolicyMemorySettings, SQLiteStore,
)
from dreamrsi.policies import DepthFirstPolicy


def build_runtime(task, saved_policy):
    return DreamRSI(
        adapter=FunctionalAgentAdapter(lambda state: {**state, "x": state["x"] / 2}),
        evaluator=lambda candidate: -(candidate["x"] ** 2),
        policy=saved_policy if saved_policy is not None else DepthFirstPolicy(),
        budget=Budget(model_calls=2, max_parallelism=1, max_depth=2),
        method=DefaultMethod(online=False),
        validation=HoldoutPipeline([
            {"kind": "numeric-halving:v1", "x": 32.0, "split": "validation"}
        ]),
    )


async def main():
    Path(".dreamrsi").mkdir(exist_ok=True)
    store = SQLiteStore(".dreamrsi/memory.sqlite3")
    try:
        memory = AdaptivePolicyMemory(
            store=store,
            runtime_factory=build_runtime,
            family_of=lambda task: task["kind"],
            raw_quality=lambda task, result: result.best_score,
            minimum_quality=lambda task: -4.0,
            settings=PolicyMemorySettings(
                accept_world=lambda current, recorded, world: (
                    current["kind"] == recorded["kind"]
                ),
                allow_training=lambda task, policy, quality, floor: False,
            ),
        )
        task = {"kind": "numeric-halving:v1", "x": 6.0}
        # Direct file transfer. OMIT this line if `dreamrsi install` already
        # imported this family into the same database and namespace.
        await memory.import_bundle("shared-policy.dreamrsi.json", task=task)
        outcome = await memory.run(task)
        print(outcome.result.best)
        print("Reused:", outcome.reused_policy, "Degraded:", outcome.degraded)
        print("Trained:", outcome.trained, "Raw quality:", outcome.raw_quality)
    finally:
        await store.close()


asyncio.run(main())
```

Passing `saved_policy` into `DreamRSI(policy=...)` is essential. Merely installing
a package does not patch arbitrary agents. Use the install command's database,
namespace and family key in `AdaptivePolicyMemory`. `reused_policy=True` means a
saved policy was used; inspect `raw_quality` and `degraded` to judge the result.

Imported trees stay in memory as replay data. When training is permitted and needed,
accepted trees are added to the runtime's replay pool, together with the new run's
accepted tree. The receiver owns independent validation tasks. To enable this path,
remove the always-false `allow_training` hook, supply fresh independent holdout tasks
for each campaign, and configure your optimizer/developer and cost budget. Do not
recycle the toy example's fixed validation task across training campaigns.

For a verified, self-contained sender-and-recipient example, run
[`examples/shared_policy_bundle.py`](https://github.com/TheAstrayDev/dream-rsi-sdk/blob/v0.2.0a2/examples/shared_policy_bundle.py)
from a checkout. It uses separate temporary SQLite files, records a real toy-agent
tree, transfers it with an explicitly supplied policy, and checks policy reuse on a
new task. This is a deterministic integration example, not an LLM benchmark.

## Compatibility and boundaries

- Family keys are application-defined. Include task/state schema and objective
  versions; assess whether the recorded agent/model behavior transfers to yours.
- `save_worlds`, `reuse_worlds`, `save_policies`, `reuse_policies`, `accept_world`,
  `accept_policy` and `allow_training` remain configurable. Policy admission is
  checked on use; importing a file is not an automatic endorsement of its policies.
- Built-in policies use the SDK codec. Source policies require the same sandbox
  profile. Custom policy classes need a receiver-registered `PolicyCodec`; use
  `install --file-only` and then import each family file with that codec. Downloading
  never installs arbitrary Python classes from a package.
- Reimporting the same data is idempotent. A different local policy history/active
  version causes a conflict; use a fresh namespace instead of replacing it silently.
  Multi-family conflicts are preflighted; disk failures are not an all-family transaction.
- `import_bundle` accepts one family file. Use CLI installation for a multi-family
  package, or import its individual files identified by `bundle_files`.
- The catalog uses GitHub stars, not quality certification. This alpha downloads
  the latest package release; version pinning and automatic upgrades are not implemented.
- Reuse can avoid repeating policy development. Original acquisition/development
  costs still exist, and transfer quality must be measured on the recipient's tasks.

See the [package guide](https://github.com/TheAstrayDev/dream-rsi-sdk/blob/v0.2.0a2/docs/packages.md)
for the workflow and the
[integration guide](https://github.com/TheAstrayDev/dream-rsi-sdk/blob/v0.2.0a2/docs/integration.md)
for embedding the runtime.

## Release validation

The staged release tree was tested separately from local benchmark files:
235 tests passed, with two optional tests skipped, on Windows / Python 3.14.
Ruff and Pyright passed. Both the runnable transfer demo and the Python code block
above were executed against separate sender/recipient databases. Wheel and source
distribution builds passed `twine check --strict`.

GitHub publication tests mock API writes; these checks do not claim a completed
live publication-and-install cycle for every third-party package. Anonymous GitHub
search rate limits can temporarily block `list`. No new paid benchmark was run for
this release.
